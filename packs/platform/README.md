# Platform binding

Where a product's parts run and what they are built with: the cloud and its accounts or projects, each environment's region, console, logs and infrastructure code, the service under each part, the stack with versions, secrets by where they are kept, the pipelines, and who decides each choice (a named person, or the builder within limits). Its briefs stop an implementing agent on any missing detail.

A binding of `software-architecture`: the design stays platform-neutral, and this pack records how it runs. The architecture finds it in `oto status` after the parts and their patterns. Its skill is `bind-platform`.

An OTO pack in the software domain: the ontology `platform` (release 1) under `ontology/`, the skill `start` that begins a project from it, and `bind-platform`. Install it in Claude Code from the registry's marketplace, or `oto pack add platform` on a machine.

`oto pack check` validates it; `oto pack refresh` re-embeds the ontology when the engine holds a newer release; `oto pack publish --to <registry>` releases it.
